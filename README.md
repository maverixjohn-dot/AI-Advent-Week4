# Погодный агент: DeepSeek + MCP + Flet

Агент на DeepSeek (`deepseek-v4-pro`, function calling) вызывает инструменты
собственного MCP-сервера, оборачивающего Open-Meteo API, и отвечает в чате
на Flet (web-режим).

## Структура

| Файл | Назначение |
|---|---|
| `mcp_weather_server.py` | MCP-сервер (stdio) + планировщик APScheduler + JSON-хранилище. Инструменты: `get_current_weather`, `get_weather_forecast`, `start_weather_collection`, `stop_weather_collection`, `set_report_schedule`, `get_new_reports`, `get_latest_report` |
| `agent.py` | Агентский цикл: DeepSeek function calling → вызовы через MCP-клиент → финальный ответ; прямой вызов инструментов `call_tool()` для фонового поллинга |
| `app.py` | Flet-приложение в web-режиме, три страницы: `/` — чат (вызовы инструментов, карточки отчётов), `/admin` — настройки сбора и расписания, `/logs` — логи приложения и MCP-сервера |
| `test_mcp_direct.py` | Тест сервера без LLM: list_tools, call_tool, обработка ошибки |
| `test_scheduler.py` | Тесты периодики: агрегация, инкрементальные отчёты, cron-расписание, реальный прогон планировщика через MCP |
| `requirements.txt` | Зависимости |

## Периодический сбор погоды и отчёты по расписанию

Параметры (переменные окружения, значения по умолчанию в скобках):

| Параметр | Переменная | По умолчанию |
|---|---|---|
| Город M | `COLLECT_CITY` | `Санкт-Петербург` |
| Интервал сбора N, мин | `COLLECT_INTERVAL_MIN` | `5` |
| Расписание отчёта, мин | `REPORT_INTERVAL_MIN` | `15` |
| Расписание отчёта, cron | `REPORT_CRON` | пусто (если задан — вместо интервала) |
| Период поллинга отчётов UI, сек | `REPORT_POLL_SEC` | `30` |

Те же параметры принимают и сами инструменты: `start_weather_collection(city,
interval_minutes)`, `set_report_schedule(interval_minutes=... ИЛИ cron=...)`.
Cron — 5 полей, например `"0 9 * * *"` (каждый день в 09:00).

Как работает:

- Сервер каждые N минут опрашивает Open-Meteo по городу M и атомарно
  дописывает замер в JSON (`weather_data.json`, переопределяется
  `DATA_JSON_PATH`).
- По расписанию сервер агрегирует замеры, накопленные с момента предыдущего
  отчёта (число замеров, средняя/мин/макс температура, сумма осадков, доля
  дождя, частотность состояний, рекомендация по зонту) и дописывает отчёт
  в тот же JSON.
- UI фоном забирает новые отчёты через `get_new_reports` и показывает их
  карточками в чате; агент отвечает на «дай сводку» через
  `get_latest_report`.
- Настройки сбора и расписания лежат в `config` внутри JSON и
  восстанавливаются при рестарте сервера.

## Страницы администрирования и логов

- **`/admin`** — город M, интервал сбора N, расписание отчёта (интервал или
  cron с переключателем), кнопки «Применить» и «Остановить сбор». Форма
  открывается с текущими значениями (читаются через инструмент `get_config`,
  с ожиданием подключения агента до 10 секунд). Применение вызывает
  `start_weather_collection` + `set_report_schedule`.
- **`/logs`** — единый лог `app_server.log`: события приложения `[app]`
  (старт сбора, действия админки) + stderr MCP-сервера (`[collect]`,
  `[report]`, ошибки циклов), который перенаправлен в файл через параметр
  `errlog` stdio-клиента (`agent.connect(errlog_path=...)`). Страница
  показывает последние 500 строк, автообновление каждые 5 секунд,
  путь переопределяется `APP_LOG_PATH`.

Важно: сервер пишет логи только в stderr — stdout занят JSON-RPC транспортом
MCP, любой print в stdout ломает протокол.

Ограничение «24/7»: сбор и отчёты работают, пока запущено приложение. Для
круглосуточной работы без UI можно запустить `mcp_weather_server.py` как
отдельный постоянный процесс и подключаться к нему.

## Запуск

```bash
pip install -r requirements.txt
python3 app.py
```

Ключ API читается из уже существующей переменной окружения `DEEPSEEK_API_KEY`
(`os.environ.get("DEEPSEEK_API_KEY")` в `agent.py`, класс `WeatherAgent`).
Ничего дополнительно задавать не нужно — переменная должна быть видна
в том shell, из которого запускается `app.py`.

Открыть http://localhost:8550

Проверка MCP-сервера отдельно (ключ не нужен):

```bash
python3 test_mcp_direct.py
```

Диагностика полного цикла DeepSeek → MCP без UI (ключ нужен,
логи каждого шага печатаются в консоль):

```bash
python3 agent.py "Что сейчас за погода в Москве?"
```

## Как это работает

1. `app.py` при старте запускает `mcp_weather_server.py` подпроцессом и
   подключается к нему по stdio (`agent.connect()`).
2. Список инструментов читается через `list_tools()` и конвертируется в
   формат `tools` OpenAI-совместимого API DeepSeek. Схемы параметров
   генерируются из type hints и docstring-ов функций с декоратором `@mcp.tool()`.
3. Сообщение пользователя уходит в `deepseek-v4-pro` вместе с инструментами.
4. Если модель вернула `tool_calls`, каждый вызов исполняется через
   `session.call_tool()`, результат добавляется в историю как сообщение
   `role="tool"`, цикл повторяется (лимит — 8 раундов).
5. Финальный текстовый ответ и трасса вызовов отображаются в чате.

## Замечания

- Ключ DeepSeek остаётся на сервере: в web-режиме Flet исполняет Python
  на стороне сервера, в браузер ключ не попадает.
- Open-Meteo не требует API-ключа.
- Зафиксировано `mcp<2`: в mcp 2.x FastMCP переименован в MCPServer, код
  написан под API v1.
- Для web-режима Flet 1.x нужен отдельный пакет `flet-web` (уже в requirements).
